# Чат для MAX на GREEN-API

Минимальный веб-чат для мессенджера MAX поверх [GREEN-API](https://green-api.com): вводишь `idInstance` и `apiTokenInstance`, указываешь номер получателя, отправляешь текст и видишь ответы. Интерфейс повторяет web.max.ru. Бэкенда нет — приложение ходит в GREEN-API прямо из браузера.

**Демо:** https://bryzzz.github.io/test_green-api/

## Возможности

- Вход по `idInstance` и `apiTokenInstance` (адрес API можно поменять), проверка статуса инстанса и предупреждение, если в настройках инстанса выключены нужные уведомления.
- Список чатов с последним сообщением, временем и счётчиком непрочитанных; новый чат по номеру телефона (проверка, что номер есть в MAX).
- Окно чата: пузыри, группировка сообщений, дни, плашка «Новые сообщения», отправка по Enter (Shift+Enter — перенос строки), статусы «отправлено / доставлено / прочитано» и понятные ошибки отправки.
- Получение сообщений через long polling, с восстановлением после потери сети («Ожидание сети…»).
- Адаптивная раскладка: на телефоне один экран (список или чат), на широком экране две колонки; кнопка «Назад» браузера возвращает из чата к списку.

## Запуск

Нужны Node.js 24 (см. `.nvmrc`) и pnpm.

```sh
pnpm install
pnpm dev          # приложение с настоящим GREEN-API
pnpm dev:mock     # приложение с фейковым GREEN-API, без инстанса
```

Остальные команды: `pnpm test`, `pnpm lint`, `pnpm typecheck`, `pnpm format`, `pnpm build`, `pnpm preview`.

### Mock-режим

`pnpm dev:mock` подменяет GREEN-API в браузере (MSW), поэтому можно пробовать приложение без инстанса и не тратить лимиты. На экране входа подойдут любые значения. Фейковый API ведёт себя так:

- номера, оканчивающиеся на `0000`, «не зарегистрированы в MAX»;
- на каждое сообщение приходят «доставлено», «прочитано» и эхо-ответ с тем же текстом примерно через 2 секунды;
- четвёртый новый чат получает ошибку лимита тарифа;
- сбои можно включать из консоли браузера: `fakeGreenApi.setFailure('network')`, `'server'` или `null`, чтобы вернуть всё как было.

Те же обработчики используются в тестах. В продакшен-сборку мок-код не попадает.

## Настройка инстанса GREEN-API

1. Зарегистрируйтесь в [консоли GREEN-API](https://console.green-api.com) и создайте инстанс для MAX.
2. Авторизуйте инстанс (QR-код или код в приложении MAX), статус должен стать `authorized`.
3. В настройках инстанса включите уведомления: входящие сообщения, исходящие сообщения и исходящие сообщения по API. Поле `webhookUrl` оставьте пустым, иначе очередь `receiveNotification` не наполняется. Приложение проверяет это при входе и предупреждает, но сам настройки не меняет.
4. Возьмите из консоли `idInstance`, `apiTokenInstance` и адрес API (для MAX сейчас `https://api.green-api.com`).

### Лимиты тарифа Developer

- до 3 чатов: четвёртый новый чат получит ошибку, она показывается на отправленном сообщении;
- 100 вызовов проверки номера (`checkAccount`), поэтому приложение запоминает найденные номера и не проверяет их повторно;
- у методов есть лимит запросов в секунду, штатная работа приложения в него не упирается.

## Хранение токена

У приложения нет сервера, поэтому `apiTokenInstance` хранится в `localStorage` браузера, как и чаты с сообщениями (отдельно для каждого инстанса). Любой скрипт на этой странице может его прочитать. Не открывайте приложение на чужом компьютере, пользуйтесь кнопкой «Выйти» (она убирает токен из браузера) и при необходимости перевыпускайте токен в консоли GREEN-API. История хранится только локально: это сообщения, полученные после входа.

## Стек

React 19, TypeScript (strict), Vite, Tailwind CSS v4, TanStack Query (запросы), Zustand (чаты и сообщения, сохраняются в `localStorage`), axios, zod (проверка ответов API), react-imask (маска телефона), Vitest + Testing Library + MSW (тесты), ESLint и Prettier.

## Архитектура

```
src/
  api/             клиент GREEN-API, ошибки, разбор уведомлений (zod)
  features/
    auth/          экран входа, проверка инстанса, хранилище учётных данных
    chats/         главный экран; chat-list, chat-window (message-list), new-chat, store
    messages/      цикл получения сообщений (runPolling) и хук useMessageReceiver
  shared/          общие кнопки и поля, форматирование времени и телефона
  mocks/           фейковый GREEN-API для тестов и `pnpm dev:mock`
  test/            общие фабрики и настройка тестов
```

- Каждый экран — один компонент в файле, рядом лежат его подкомпоненты, хуки, `lib/` с чистыми функциями и тест.
- Получение сообщений — не кэшируемый запрос, а цикл с побочным эффектом: `receiveNotification` → обработка → `deleteNotification`. Он вынесен в `runPolling` без привязки к React, поэтому тестируется отдельно.
- Ошибки сети приводятся к одному типу `ApiError` с полем `kind`, интерфейс работает только с ним.
- Пути импорта через алиас `@/` (это `src/`).
